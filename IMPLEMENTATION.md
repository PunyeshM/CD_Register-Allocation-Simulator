# Implementation Details

The Register Allocation Simulator is constructed using a robust C++17 backend for the core algorithm and a Next.js (React) frontend for visualization.

## Core Data Structures

- **`Instruction`**: Represents a single LLVM IR instruction. It maintains its opcode (e.g., `ADD`, `LOAD`), operands (uses), and result (def). Variables are tracked as strings prefixed with `%`.
- **`BasicBlock`**: A container for a sequence of `Instruction` objects representing straight-line code with no branches except at the entry and exit.
- **`LivenessAnalyzer`**: Maintains the `IN`, `OUT`, `DEF`, and `USE` sets. Computes liveness iteratively using `std::set` operations.
- **`InterferenceGraph`**: Represented via an adjacency list mapping a node string to a set of neighboring node strings. It tracks degrees and edges to facilitate coloring.
- **`RegisterAllocator`**: Executes Chaitin's algorithm using a stack for simplification and handles color assignments and spill detection.

## LLVM IR Details and Parsing

The simulator processes a subset of LLVM IR natively generated by LLVM frontends like Clang. 

### Supported Instructions
- **Arithmetic**: `add`, `sub`, `mul`
- **Memory**: `load`, `store`
- **Control Flow/SSA**: `phi`, `ret`

### Def-Use Extraction
In LLVM IR, instructions typically follow an SSA (Static Single Assignment) form. 
- *Definition*: The left-hand side of the instruction (e.g., `%1` in `%1 = add i32 %a, %b`).
- *Uses*: The operands on the right-hand side (e.g., `%a`, `%b`).

For specific instructions:
- `store %val, %ptr`: Uses both `%val` and `%ptr`, defines nothing.
- `load %ptr`: Uses `%ptr`, defines a new SSA value.
- `ret %val`: Uses `%val`, defines nothing.

The backend parses these definitions and uses from the raw IR strings and automatically builds the necessary `std::set` structures for backward dataflow equations.

## Integration with Visualization (Frontend)

The backend outputs the results of every phase into a structured JSON file (`graphs/analysis.json`), which includes:
- The parsed IR.
- The step-by-step Liveness analysis iterations.
- The adjacency list of the Interference Graph.
- The final assignments, simplification stack, and spills.

The Next.js frontend fetches this JSON and visually renders the LLVM IR, dynamically generates the interference graph using D3.js (Force-directed graph), and animates the Chaitin coloring process step-by-step to provide interactive LLVM compiler education.
